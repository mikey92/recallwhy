# Examples (real runs, not edited)

Each `report.html` opens with a "What the agents did" banner per case, built only from that case's trace. Each request in `input/` was sent to `POST /run` on the API (`npm run api`) with live Zetaris, Meterless Nightshift and `nvidia/nemotron-3-ultra-550b-a55b`, on 24 Oct 2026 (after the data change), starting from empty H-MEM and World Model state. `output/example_N.json` is the API's response, unchanged. `output/example_N/` holds the run's full `trace.jsonl` and its `report.html` / `report.md` (open the HTML in a browser). The `trace` and `outDir` paths inside the JSON point at where the files were written in the working copy.

| Request | Response | What to look for in `trace.jsonl` (seq) |
|---|---|---|
| `example_1.json`: recalls since 2026-09-15, first 5 | 2 act-now, 2 not-ours, 1 needs-human | 3, 12: the Cartographer reads Zetaris's catalog (`SHOW DATASOURCES`, `SHOW LIGHTNING DATABASES`, …). 40: it profiles how the live feeds write barcodes and dates. 46: the Scout's REST × JDBC join (live FDA feed × ERP). 365: a judge call answered by `nvidia/nemotron-3-ultra-550b-a55b` (`served_model`, `receipt`). 405–420: the judge dismisses a SKU whose own quote names it; the Auditor blocks the dismissal three times (`dismissal-names-our-item`) and the case is escalated to a human. 413–414 and later: `llm.retry` after rate limits. 478–482: the Auditor sends ship-notice rows its barcode key cannot reach to the Cartographer, which learns that SUP007 drops the UPC check digit, checks it on all 484 of SUP007's ship notices, and corrects the map. |
| `example_2.json`: H-1355-2026 and H-1378-2026 | 2 act-now | 75–79: the same Auditor → Cartographer correction, in a two-case run you can read end to end. |
| `example_3.json`: recalls since 2026-10-01, first 3 | 1 act-now, 1 not-ours, 1 needs-human | 137–155: the judge dismisses NW-100005 although its quote names our item; the Auditor blocks the dismissal three times and the case goes to a human. 138, 166–169: `llm.retry` after rate limits; every call got through. |
| Human review, then `example_3.json` again → `example_3_after_human_decision.json` | 2 act-now, 1 not-ours | Between the runs: `POST /decide` for H-1407-2026 NW-100005 `same`, note "same Todd's Seeds broccoli sprouting mixture and vendor; our 4LB size is not one of the notice's sizes (1/4, 1/2, 1 lb), likely an item-master error, so treat it as recalled until receiving confirms the bag size" — a reviewer choosing the safe side, not the data agreeing. 135–136: the Investigator follows the stored human decision (`mem-13`) without asking the model. 146–152: SUP010 sends a 10-digit barcode core no rule in the code covers; the Auditor sends the rows back (146), Nemotron 3 Ultra proposes a transform (149), and it is adopted only after Zetaris SQL proves it on every SUP010 ship notice (150, 299 of 299). |
| `example_1.json` with `SAMPLE_MODE=true LLM_PROVIDER=none`, from empty state → `example_1_sample_mode.json` | 2 act-now, 3 needs-human | What a judge without Zetaris or Nightshift sees: the same agents and SQL on the DuckDB stand-in and no model calls, so the three text matches go to the review queue (`GET /queue`, or `/review` in the viewer) instead of being guessed. 492–496: the Auditor → Cartographer correction happens here too. |

The Nightshift calls hit the hosted NVIDIA rate limit during these runs (the `llm.retry` events); with up to five waits (3–90 s) every call got through.
