# Examples (real runs, not edited)

Each `report.html` opens with a "What the agents did" banner per case, built only from that case's trace. Each request in `input/` was sent to `POST /run` on the API (`npm run api`) with live Zetaris, Meterless Nightshift and `nvidia/nemotron-3-ultra-550b-a55b`, on 24 Oct 2026 (after the data change), in this order, starting from empty H-MEM and World Model state; later runs read what earlier ones stored (example_2 reuses decision mem-7 from example_1, the second example_3 run reuses mem-11 from the first). `output/example_N.json` is the API's response, unchanged. `output/example_N/` holds the run's full `trace.jsonl` and its `report.html` / `report.md` (open the HTML in a browser). The `trace` and `outDir` paths inside the JSON point at where the files were written in the working copy.

| Request | Response | What to look for in `trace.jsonl` (seq) |
|---|---|---|
| `example_1.json`: recalls since 2026-09-15, first 5 | 2 act-now, 2 not-ours, 1 needs-human | 3, 12: the Cartographer reads Zetaris's catalog (`SHOW DATASOURCES`, `SHOW LIGHTNING DATABASES`, …). 40: it profiles how the live feeds write barcodes and dates (CPSC: 189 notices). 46: the Scout's REST × JDBC join (live FDA feed × ERP). 435: a judge call answered by `nvidia/nemotron-3-ultra-550b-a55b` (`served_model`, `receipt`). 475–488: the judge dismisses a SKU whose own quote names it; the Auditor blocks the dismissal three times (`dismissal-names-our-item`) and the case is escalated to a human. 540–549: the Auditor sends ship-notice rows its barcode key cannot reach to the Cartographer, which learns that SUP007 drops the UPC check digit, checks it on all 484 of SUP007's ship notices (542), writes the corrected map back to Zetaris as the view `reconciled.ship_notice_item_keys` and reads SUP007 back from it, 484 of 484 (546–547). |

The hosted NVIDIA endpoint answers about 4 calls a minute; the client paces `nvidia/*` calls and retries the rest (`llm.retry` events), and every call got through.
